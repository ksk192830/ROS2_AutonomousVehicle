## 제3회 프로젝트 현재 상태

- 사용자 정의 ROS 메시지 `interfaces_pkg` 이관
- `decision_making_pkg`와 주차 FSM 이관
- `control_pkg`/Arduino 펌웨어 이관, 시리얼 장치 파라미터화
- 카메라 인지 노드와 주요 launch 파일 이관, 모델·장치 설정 분리
- 원본에서 제공된 컴파일된 `.pyc` 및 불필요한 학습 체크포인트는 제외
- 런타임 모델 `final.pt`는 이전에 Git LFS로 등록했으나 **공개 저장소의 현재 파일 목록에서 제거**했습니다. 필요할 경우 권한 있는 사용자가 로컬에서 별도로 준비해야 합니다. 이관 과정에서 ROS 2 빌드·실행 검증은 수행하지 않음. 환경에 따라 수정이 필요할 수 있음

## 유지 원칙

- 대회별 독립 ROS 2 워크스페이스
- 당시 알고리즘을 보존하고 환경 종속성만 최소 수정
- 학습된 모델 가중치는 공개 저장소에서 제외하고 로컬에서 별도 준비. TensorRT 엔진은 환경별 생성
- 외부 저작권 및 라이선스 고지는 삭제하지 않음

## 제4회 프로젝트 현재 상태

- 카메라·LiDAR·판단·제어·메시지·launch·시뮬레이션의 **ROS2 7개 패키지**, Arduino 펌웨어, 도구 스크립트 및 텍스트 기반 Gazebo 월드/설정 등 **150개 텍스트 파일 선별 이관**
- 원본 Git 커밋 기록, 캐시, 약 750장의 학습/영상 이미지, 중간 실험 데이터는 복사하지 않음
- 모델 파일 `track.pt`, `parking_front.pt`, `parking_rear.pt`, `crosswalk.pt`, `traffic_light_sim.pt` **공개 저장소에서 제거**했습니다. 실행을 위해서는 로컬에서 별도 준비해야 합니다. 추가 시뮬레이션 가중치 `sim.pt`는 미등록
- `track.engine`과 `parking_front.engine`은 원본 GPU/TensorRT 버전에 종속된 파일로 **이관 대상에서 제외**. 해당 launch는 그대로 엔진을 요구할 수 있어 별도 엔진 생성/검토 필요. RF-DETR TensorRT 노드를 YOLO `.pt` 노드로 임의 대체하지 않음
- Gazebo 메시·텍스처·차량 모델 바이너리와 3D 프린팅 CAD/STL 파일은 아직 이관되지 않음. 월드/SDF 텍스트만으로 시뮬레이션이 실행된다고 보장할 수 없음
- 개인 홈 절대경로를 보조 도구와 시나리오 실행 스크립트에서 프로젝트 기준 경로로 변경
- **ROS 2 빌드와 3개 시뮬레이션 launch 인자 로딩을 CI에서 확인**. GPU 추론·Gazebo 주행·실차 동작은 재검증하지 않음

## 경기도 자율주행 경진대회 현재 상태

- 카메라, LiDAR, 판단, 제어, 인터페이스의 **ROS2 5개 패키지**와 일반·미션·주차 launch, Arduino, 보조 도구 등 **93개 텍스트 소스·설정 파일 이관**
- 원본 소스에 있던 개발자 개인 홈 경로를 패키지 공유 경로 또는 사용자 캡처 경로로 변경; RViz 및 지도 YAML 설치 경로 명시
- 런타임 가중치 `track.pt`, `parking_front.pt`, `parking_rear.pt` **공개 저장소에서 제거했습니다**
- 주차 지도 이미지 `convenient/parking_map/map_image.png` 등록 완료
- 차 이미지 `car.png`, 테스트 영상 이미지, CAD/STL 등은 포함하지 않음(시각화 선택 자산·재배포 권한 별도 확인)
- 원본 알고리즘·상태전이 로직은 이관 외 임의 변경하지 않음
- **ROS2 빌드·실행 검증은 수행하지 않았으므로** 환경에 따라 수정이 필요할 수 있음

## Gazebo 시뮬레이션 (Expo 전시 + 이후 실험) 이관 현황

- 같은 `src/`를 공유하면서 `exhibition/`(Expo 전시 구성·상호작용 안내), `testing/`(향후 자율주행 로직 교체와 시나리오 실험 안내)로 분리 문서화
- 원본 Expo 브랜치의 ROS2 9개 패키지·Gazebo SDF/URDF·RViz·전시 스크립트 등 **텍스트 253개 이관**. 전시 GUI 이미지 7개 보존. 대표 전시 화면 캡처 2개는 포트폴리오 정리 과정에서 제거
- 원본 MIT 고지 및 제3자 에셋의 저작권 귀속 파일 보존; 라이선스 표기가 서로 다른 패키지는 별도 범위 검토 필요
- Gazebo 3D 메시/텍스처와 AI 가중치(.pt/.pth), 90MB 이상의 시뮬레이션 가중치는 아직 공개 저장소에 복사하지 않음
- `projects/autonomous_simulation/scripts/import_runtime_assets.sh`로 소유자가 접근 권한을 가진 원본에서 핵심(`core`)/전시(`expo`)/전체(`all`) 바이너리를 로컬에 선택 복구할 수 있도록 구성. 공개 저장소에 자동 업로드하지 않음
- **ROS 2 빌드와 3개 시뮬레이션 launch 인자 로딩을 CI에서 확인**. GPU 추론·Gazebo 주행·전시 전체 흐름은 재검증하지 않음

## 다른 PC 재현 준비 보완

- 제4회 카메라 패키지의 로컬 TensorRT 엔진 설치와 시뮬레이션 주차 지도 설치 경로 보완
- 시뮬레이션 Python 로더의 워크스페이스 깊이 의존 경로 제거, 모델을 ROS 패키지 공유 경로에서 조회
- 직접 사용하는 ROS/Python 시스템 의존성 선언 보완
- 원본 접근 권한을 가진 사용자의 로컬 자산 복구 도구 및 시나리오별 파일 점검 도구 추가
- Ubuntu 22.04 / ROS 2 Humble 독립 빌드 workflow와 재현 안내 추가

자산 복구는 공개 배포가 아닙니다. TensorRT 엔진 생성, GPU 추론, Gazebo 주행과 실차 동작은 대상 환경에서 별도 검증해야 합니다. 절차는 [재현 안내](reproduction.md)를 참조합니다.

현재 확인된 ROS 빌드 및 실행 파일 로딩 범위는 [재현 준비 검증 기록](validation.md)을 기준으로 확인합니다. 프로젝트별 빌드 확인 여부와 실제 주행 재검증 여부를 구분합니다.
